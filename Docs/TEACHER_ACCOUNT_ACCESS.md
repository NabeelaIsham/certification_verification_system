# Teacher invitations and password recovery

- Creating a teacher in **Teachers** no longer asks the institute admin to choose a password. The account receives a random, undisclosed password; an email tells the teacher their account is active and links to `/teacher/set-password` to choose their own password. Successful setup leads to sign-in, including existing two-factor checks where enabled.
- Under **Teachers → Reset access**, the owning institute can send another link or expand **Set a new password directly**. Direct changes are useful when email recovery is unavailable. Passwords are never emailed. Resetting an inactive account does not activate it.
- Links use a random 256-bit secret, stored only as a hash, expire after 24 hours, and are replaced by newer links. The link secret is in the URL fragment, not the HTTP path/query; the page removes it from the address bar after loading. Reloading that page requires reopening the original email link.
- A successful reset is transactional and single-use, increments the session version, removes reset codes and login challenges, and records an audit event without passwords or tokens. Tenant and role checks restrict admin actions to that institute's teachers. Sending another link has a one-minute per-teacher cooldown and password endpoints also have rate limits.
- Set `FRONTEND_URL` (or `FRONTEND_BASE_URL`) to the public frontend origin, using HTTPS in production, and configure the existing SMTP settings. Links are never built from a request Host header.
- SMTP sending is attempted during account creation. On failure, the account remains created, the unusable link is removed, and the admin sees a delivery warning. There is no automatic invitation email queue in this change: correct the email settings and choose **Send reset link** to retry. A successful SMTP response means accepted for delivery, not confirmed inbox receipt.
- Existing API clients may still supply a valid password at creation for compatibility, but also receive the invitation attempt. Existing teachers are not automatically emailed. No real external email or production change is performed by tests.
